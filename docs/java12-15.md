# Java 12 – 15: the road to records and text blocks

Four releases, March 2019 to September 2020. None of them is LTS, and nobody
ran them in production for long. Their importance is that this is where the
**preview mechanism** did its work: switch expressions, text blocks, records
and pattern matching all landed here as previews, took feedback, and shipped
as standard features in 14, 15, 16 and 21.

Read this chapter as the origin story for the things you actually use.

---

## How previews work

Introduced in Java 12 (JEP 12). A preview feature is complete and fully
implemented, but not yet permanent — the design can still change or be withdrawn.

```bash
javac --release 25 --enable-preview Example.java
java  --enable-preview Example
```

Two rules make previews safe to experiment with and unsafe to ship:

- **Both flags are required**, at compile time and at run time.
- **A class file compiled with `--enable-preview` refuses to load on any other
  JDK version**, including a newer one. There is no accidental leakage into
  production.

The mechanism has been used honestly. String Templates were previewed in 21,
previewed again in 22, and then **withdrawn entirely in 23** — exactly what the
process is for.

## Java 12 (March 2019)

### `Collectors.teeing`

**Code:** [`jdk12/CollectorsTeeing`](../src/main/java/com/tomtom/genesis/platform/jdk12/CollectorsTeeing.java)

Feeds every element into two collectors at once and merges the results:

```java
record Summary(long count, double total) { }

Summary s = orders.stream()
        .filter(o -> o.amount() > 60)
        .collect(Collectors.teeing(
                Collectors.counting(),
                Collectors.summingDouble(Order::amount),
                Summary::new));
```

The alternative was traversing the stream twice. For an in-memory list that is
merely wasteful; for a stream backed by a file, a cursor or a network call the
second traversal is impossible — a stream can only be consumed once.

The name comes from a plumbing tee: one input, two outputs.

Do not reach for it when `Collectors.summarizingDouble` already gives you
count, sum, min, max and average in one object.

### `String.indent` and `String.transform`

**Code:** [`jdk12/SmallAdditions12`](../src/main/java/com/tomtom/genesis/platform/jdk12/SmallAdditions12.java)

```java
block.indent(4)                 // shift every line right by four spaces
block.indent(-3)                // remove up to three leading spaces
" 42 ".transform(String::strip).transform(Integer::parseInt)
```

Two details about `indent`: it **always appends a trailing newline**, even
`indent(0)`, and it normalises line endings to `\n`.

`transform` exists to make a chain read in execution order. Note it returns `R`,
not `String` — so the chain can change type at any step. That is what makes it
more than sugar.

### `Files.mismatch`

```java
Files.mismatch(a, b)    // -1 if identical, else the index of the first differing byte
```

Short-circuits on the first difference, unlike
`Arrays.equals(Files.readAllBytes(a), Files.readAllBytes(b))`, which loads both
files into memory first. If one file is a prefix of the other, it returns the
length of the shorter one.

### Compact number formatting

```java
NumberFormat.getCompactNumberInstance(Locale.US, Style.SHORT).format(2_400_000)  // "2M"
```

Real output from the example, showing why locale data matters:

```
          value | SHORT en | LONG en          | SHORT pl
            999 |      999 | 999              |      999
         15.300 |      15K | 15 thousand      |  15 tys.
      2.400.000 |       2M | 2 million        |    2 mln
  7.000.000.000 |       7B | 7 billion        |    7 mld
```

## Java 13 (September 2019)

A thin release from an API point of view. Its content was previews: text blocks
(first preview) and switch expressions (second preview, where `yield` replaced
the earlier `break value` syntax).

| Change | Note |
|---|---|
| **Dynamic CDS archives** (JEP 350) | Generate the class-data archive at application exit instead of configuring it up front |
| **ZGC returns memory** (JEP 351) | Uncommits unused heap back to the OS — important for containers and for anything billed by memory |
| **Socket API reimplemented** (JEP 353) | The 1996 implementation of `Socket`/`ServerSocket` replaced. Groundwork for virtual threads: the old one used stack-allocated native buffers that could not be unmounted |

## Java 14 (March 2020)

### Switch expressions — standard (JEP 361)

**Code:** [`jdk14/SwitchExpressions`](../src/main/java/com/tomtom/genesis/platform/jdk14/SwitchExpressions.java)

Four improvements arrived as one feature.

**Arrow labels — no fall-through, no `break`:**

```java
switch (day) {
    case MONDAY, TUESDAY -> earlyWeek();
    case SATURDAY, SUNDAY -> weekend();
    default -> other();
}
```

Only the matching branch runs, as a language rule rather than a convention.
Each arrow branch gets its own scope, so two branches may declare the same
variable name.

**switch as an expression:**

```java
int priority = switch (status) {
    case NEW -> 1;
    case IN_PROGRESS -> 2;
    case DONE, CANCELLED -> 0;
};
```

The variable can now be `final` and assigned exactly once. Note the semicolon
after the closing brace — it is an expression, so the statement still needs
terminating.

**`yield` for block branches:**

```java
case DONE, CANCELLED -> {
    String suffix = status == DONE ? "successfully" : "by the user";
    yield "finished " + suffix;
}
```

`yield` is to a switch expression what `return` is to a method. It is a
*restricted identifier*, not a keyword — code with a variable named `yield`
still compiles.

**Exhaustiveness — the most valuable part:**

A switch *expression* must cover every possible value, and over an enum the
compiler verifies it:

```java
int p = switch (status) {
    case NEW -> 1;
    case IN_PROGRESS -> 2;
};   // error: the switch expression does not cover all possible input values
```

Practical advice: over an enum, **deliberately omit the `default` branch**. A
default swallows new constants and hands you a fallback at runtime; without it,
adding a constant to the enum breaks the build at every place that needs updating.

A switch *statement* is not required to be exhaustive — the rule applies to
expressions only.

### Helpful NullPointerExceptions (JEP 358)

**Code:** [`jdk14/HelpfulNullPointerExceptions`](../src/main/java/com/tomtom/genesis/platform/jdk14/HelpfulNullPointerExceptions.java)

Opt-in in 14 (`-XX:+ShowCodeDetailsInExceptionMessages`), **on by default since 15**.

Real messages from the example:

```
Cannot invoke "Address.city()" because the return value of "Customer.address()" is null
Cannot load from object array because "grid[1]" is null
Cannot invoke "java.lang.Integer.intValue()" because the return value of "java.util.Map.get(Object)" is null
Cannot read field "city" because "customer.address" is null
```

The third one is the best return on the feature. `Map.get` returns null for a
missing key, and assigning it to an `int` calls `intValue()` on null — an NPE
on a line with no visible method call at all.

Limits: the message is reconstructed from bytecode, so it needs local variable
names in the class file. Code compiled with `-g:none` produces `<local1>`. It
tells you what the bytecode did, never why the value was null. Turn it off with
`-XX:-ShowCodeDetailsInExceptionMessages` if a message could leak sensitive data
into logs.

## Java 15 (September 2020)

### Text blocks — standard (JEP 378)

**Code:** [`jdk15/TextBlocks`](../src/main/java/com/tomtom/genesis/platform/jdk15/TextBlocks.java)

```java
String json = """
        {
          "name": "Ala",
          "city": "Lodz"
        }""";
```

Syntax rules: the opening `"""` must be followed by a line terminator (a
one-line `"""x"""` is a compile error); a double quote inside needs no escaping;
the result is an ordinary `String`, produced at compile time, so it can be a
constant and can be interned.

**Incidental whitespace is the part that trips everyone up.** The algorithm
takes every non-blank content line *and the line holding the closing delimiter*,
finds the smallest leading-whitespace count among them, and strips that many
characters from every line. Real output from the example:

```
aligned (closing delimiter level with the content):
[line one
line two]

indented (closing delimiter moved left):
[    line one
    line two
]
```

The position of the closing `"""` is not cosmetic — moving it left adds
indentation to your string. Trailing whitespace on each line is always stripped.

**Whether the block ends with a newline** is also controlled by the closing
delimiter: on its own line, the string ends with `\n`; immediately after the
last character, it does not.

**Two escapes exist only here:**

- `\` at end of line — suppress the line break. Useful for a long SQL statement
  you want to read across several lines but send as one.
- `\s` — a literal space that survives trailing-whitespace stripping.

**There is no interpolation.** `${name}` is literal text. Use `formatted()` or
concatenation. String Templates (`STR."Hello \{name}"`) were previewed in 21 and
22 and **withdrawn in 23** — if you find a tutorial showing that syntax, it
describes a preview that no longer exists.

### The three companion String methods

```java
template.formatted("Ala", "Lodz")   // String.format with the receiver swapped in
messy.stripIndent()                 // the text-block algorithm, on a normal string
escaped.translateEscapes()          // turn \t and \n sequences into real characters
```

`formatted` matters for readability: the format sits at the top as a block and
the arguments follow the closing delimiter, instead of the whole block being
buried inside a `String.format(...)` call.

`translateEscapes` is what you want when escape sequences arrive at runtime from
a config file or user input, where the compiler never saw them.
